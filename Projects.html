Core Services

Tailscale

What it is: Tailscale is a mesh VPN built on WireGuard. It links your computers, servers and phones into one private network (a “tailnet”), so they can reach each other securely from anywhere without opening ports on your router.

Connect to your remote server via SSH:

bash 
ssh user@your_server_ip

Ensure you have sudo privileges on the target machine.

Install Tailscale

Update package list (Debian/Ubuntu):

bash 
sudo apt update && sudo apt install -y curl

Download & install Tailscale:

bash 
curl -fsSL https://tailscale.com/install.sh | sh

This installs the latest version for your OS automatically.

Authenticate Server

Start Tailscale service:

bash 
sudo tailscale up

You will see an authentication URL: "To authenticate, visit: https://login.tailscale.com/a/xxxxxx"

Copy the URL from SSH output and open it on your local browser.

  • Log in with your preferred identity provider (Google, GitHub, Microsoft, etc.)
  • Once authenticated, the machine will appear in your Tailscale admin dashboard.

SSH

What it is: SSH (Secure Shell) is the standard way to log in to and manage a Linux machine from another computer. Everything you type and see is encrypted, so you can run commands on a server as if you were sitting in front of it.

Install OpenSSH Server:

bash 
sudo apt update
sudo apt upgrade
sudo apt install openssh-server -y

Verify it is running:

bash 
sudo systemctl status ssh

Allow through the Firewall:

bash 
sudo ufw allow ssh

Key-Based Authentication

What it is: Key-based authentication replaces SSH passwords with a key pair: a private key that never leaves your computer and a public key you copy to the server. It is far harder to crack than a password and lets you log in without typing one.

Docker

What it is: Docker runs applications in containers: lightweight, isolated packages that bundle an app with everything it needs. A container runs the same way on any machine, so installing, updating or removing a service is one command and never clutters the host system.

Documentation: https://docs.docker.com/engine/install

# Add Docker's official GPG key:

bash 
sudo apt update
sudo apt install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Add the repository to Apt sources:

bash 
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc
EOF

Install the Docker packages:

bash 
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo apt update
sudo systemctl status docker
sudo systemctl start docker
sudo docker run hello-world

Docker Compose

What it is: Docker Compose describes one or more containers (their images, ports, volumes and settings) in a single docker-compose.yml file, then starts or stops the whole stack with one command. It is how most of the self-hosted apps on this page are deployed.

Documentation: https://docs.docker.com/compose/install/

CURL

What it is: curl is a command-line tool for sending and receiving data over URLs. It is used to download files and install scripts, test websites and APIs, and check whether a service is responding.

bash 
sudo apt install ca-certificates curl

Htop

What it is: htop is an interactive, color-coded process viewer for the terminal. It shows live CPU, memory and swap usage alongside every running process, and lets you sort, search and stop processes. It is the quickest way to see what is slowing a server down.

Depending on your Linux distribution, use the corresponding command below:

For Ubuntu, Debian, Linux Mint, or Kali:

bash 
sudo apt update
sudo apt install htop

For CentOS, RHEL, or Rocky Linux:

bash 
# First, enable the EPEL repository
sudo dnf install epel-release
# Then install htop
sudo dnf install htop

For Fedora:

bash 
sudo dnf install htop

For Arch Linux:

bash 
sudo pacman -S htop

How to use htop

Once installed, simply type htop in your terminal to launch it.

Quick Cheat Sheet for htop:

Once the interface is open, you can use these keyboard shortcuts to navigate:

  • F2 (Setup): Customize the colors, meters, and columns.
  • F3 (Search): Find a specific process by name.
  • F4 (Filter): Hide everything except processes matching your keyword.
  • F5 (Tree): See the parent-child relationship between processes.
  • F6 (Sort): Choose to sort by CPU%, Memory%, PID, etc.
  • F9 (Kill): Send a signal (like SIGKILL) to stop a process safely.
  • F10 (Quit): Exit the program.

Vim/Nano

What it is: Vim and Nano are text editors that run in the terminal, used to edit configuration files directly on a server. Nano is simple, with its shortcuts listed at the bottom of the screen; Vim is more powerful and keyboard-driven, with a steeper learning curve.

Installation Steps

For Ubuntu, Debian, or Raspberry Pi OS:

bash 
sudo apt update
sudo apt install nano vim

For CentOS, RHEL, or Rocky Linux:

bash 
sudo dnf install nano vim-enhanced

For Arch Linux:

bash 
sudo pacman -S nano vim

How to use them

Using Nano:

  • To open a file: nano filename.txt
  • Save: Press Ctrl + O then Enter.
  • Exit: Press Ctrl + X.
  • Search: Press Ctrl + W.

Using Vim:

  • To open a file: vim filename.txt
  • Type Text: Press i to enter Insert Mode.
  • Stop Typing: Press Esc to return to Normal Mode.
  • Save & Exit: In Normal Mode, type :wq and hit Enter.
  • Exit without Saving: In Normal Mode, type :q! and hit Enter.

Net-tools

What it is: Net-tools is a package of classic Linux networking commands such as ifconfig, netstat, route and arp. They show network interfaces and IP addresses, open ports and connections, and the routing table, which makes them handy for troubleshooting connectivity.

Installation Steps

For Ubuntu, Debian, Linux Mint, or Kali:

bash 
sudo apt update
sudo apt install net-tools

For CentOS, RHEL, Fedora, or Rocky Linux:

bash 
sudo dnf install net-tools

For Arch Linux:

bash 
sudo pacman -S net-tools

What's inside net-tools

Command What it does Modern Replacement (iproute2)
ifconfig View/Configure network interfaces ip addr
netstat -tuln See active ports and connections ss -tuln
route -n View the routing table ip route
arp -a View the ARP table (IP-to-MAC mapping) ip neigh

Quick Examples

  • Check your IP address:

    Simply type ifconfig. You'll see your hardware address (MAC), your local IP (inet), and data packet statistics

  • Check listening ports:

    sudo netstat -plnt. This shows which programs are listening on which ports (e.g., port 80 for HTTP)

  • Check your default gateway:

    route -n

    From Windows:

    1. Open File Explorer
    2. In the address bar, type: \\<YOUR_STATIC_IP>\PublicShare (e.g., \\192.168.38.120\PublicShare)

    Parameter Meaning
    path The actual directory on your Linux disk

    Part 1: Hosting Your Website for Free (GitHub Pages)

    GitHub Pages is a free service that hosts your static files directly from a GitHub repository.

    1. Create a GitHub Account: Go to github.com and sign up or log in
    2. Create a New Repository:
      • Click your profile icon (top right) > Your repositories > New
      • Give it a name (e.g., my-website) and ensure it is set to Public
    3. Upload Your Files:
      • Click "uploading an existing file".
      • Drag and drop your index.html (and any CSS/Images) into the box.
      • Scroll down and click Commit changes.
    4. Enable GitHub Pages:
      • Go to Settings (top tab) > Pages (left sidebar).
      • Under Build and deployment, ensure "Deploy from a branch" is selected and the branch is set to main.

    Part 2: Using a Custom Domain (Namecheap)

    If you want a professional address (like www.yourname.com), you need to point your domain to GitHub's servers.

    1. Buy a Domain: Purchase one from Namecheap.
    2. Configure GitHub:
      • In your GitHub Repo Settings > Pages, scroll to Custom domain.
      • Type your domain (e.g., yourname.com) and click Save.
    3. Configure Namecheap (DNS Records):
      • Log in to Namecheap > Domain List > Manage > Advanced DNS.
      • Add four A Records pointing to GitHub's IP addresses:
        • 185.199.108.153
        • 185.199.109.153
        • 185.199.110.153
        • 185.199.111.153
      • Add a CNAME Record:
        • Host: www
        • Value: your-username.github.io
    4. Link Domain in GitHub:
      • Return to your GitHub repository Settings > Pages.
      • Under Custom domain, type your new domain (e.g., example.com) and click Save.

    Windows Server

    Section 1: Initial Server Setup & Role Installation

    Before beginning, ensure your server has a static IP address configured (e.g., 192.168.49.5)

    1. Open Server Manager: Click Manage > Add Roles and Features
    2. Select Installation Type: Choose Role-based or feature-based installation and select your server
    3. Select Server Roles: Check the boxes for:
      • Active Directory Domain Services (AD DS)
      • DHCP Server
      • DNS Server
      • Note: Click "Add Features" whenever prompted for management tools.
    4. Install: Follow the prompts and click Install
    5. Promote to Domain Controller: Once installed, click the notification flag and select Promote this server to a domain controller
    6. Deployment: Select Add a new forest and enter your Root domain name (e.g., mylab.local)
    7. Configuration: Set a Directory Services Restore Mode (DSRM) password and complete the wizard
    8. The server will automatically reboot after installation.

    Section 2: DNS - Configuring Lookup Zones

    Active Directory creates Forward Lookup Zones automatically, but you must manually configure the Reverse Lookup Zone.

    Configuring Reverse Lookup Zones:

    1. Open DNS Manager: Go to Tools > DNS
    2. Create New Zone: Right-click Reverse Lookup Zones > New Zone
    3. Select Primary Zone and check "Store the zone in Active Directory"
    4. Replication Scope: Select "To all DNS servers running on domain controllers in this domain"
    5. Select IPv4 Reverse Lookup Zone
    6. Network ID: Enter the first three octets of your network (e.g., 192.168.49).
    7. Dynamic Updates: Choose Allow only secure dynamic updates
    8. Add Pointer (PTR) Record:
      • Right-click your new zone > New Pointer (PTR)
      • Browse to find your Host (A) record in the Forward Lookup Zone to map the IP to the Hostname
    9. Final DNS Tweak: In your Ethernet adapter settings, change the Preferred DNS server from 127.0.0.1 to the server's actual static IP (192.168.49.5)

    Section 3: DHCP - Post-Install & Scope Configuration

    1. Post-Deployment: Click the notification flag in Server Manager and select Complete DHCP configuration
      • This creates security groups and authorizes the server in Active Directory
    2. Open DHCP Manager: Go to Tools > DHCP
    3. Create New Scope: Right-click IPv4 > New Scope
    4. Name: Provide a name (e.g., Scope1)
    5. IP Range: Enter Start (e.g., .20) and End (e.g., .250) addresses
    6. Lease Duration: Set to desired time (e.g., 8 hours)
    7. Configure DHCP Options:
      • Router (Default Gateway): Add your gateway IP (e.g., 192.168.49.1)
      • DNS Server: Ensure your Domain Controller IP is listed
    8. Activate: Select Yes, I want to activate this scope now

    Section 4: Joining a Client to the Domain

    1. Client Network Check: On a Windows 10 PC, ensure the adapter is set to "Obtain IP address automatically"
    2. Run ipconfig /all to verify it received an IP from the new DHCP server
    3. Join Domain:
      • Go to Settings > System > About > Join a domain
      • Enter the domain name (mylab.local) and provide Domain Administrator credentials
      • Restart the client computer
    4. Verify: In Server Manager, go to Active Directory Users and Computers > Computers to see the newly joined client listed

    NGINX

    NGINX is a web server most often used as a reverse proxy: it receives every request on ports 80/443, handles HTTPS, and forwards each request to the right app based on its domain name (for example vault.tail.example.com → Vaultwarden on port 1776). This guide uses Nginx Proxy Manager (NPM), which runs NGINX in Docker with an easy web interface and free Let’s Encrypt certificates.

    These steps follow the first half of the video tutorial in the Vault Warden section, where NPM is the reverse proxy for a private, Tailscale-only Vaultwarden server.

    Video Tutorial: https://youtu.be/AwJXizTdth0

    Before You Start

    • An Ubuntu server you can reach over SSH (see SSH). The video starts from a freshly cloned Ubuntu VM.
    • Docker Engine installed from Docker’s official apt repository (see Docker).
    • A domain name whose DNS is managed by Cloudflare (other DNS providers work too; the steps are similar).

    ▶ Watch this step (0:51)

    Confirm Docker and the Compose plugin are installed:

    bash 
    sudo docker --version
sudo docker compose version

    Install Nginx Proxy Manager

    ▶ Watch this step (1:22)

    Step 1: Create a folder for your Docker apps

    Keep every app in its own folder under ~/docker:

    bash 
    mkdir -p ~/docker/npm
cd ~/docker/npm

    Step 2: Create the Compose file

    bash 
    nano docker-compose.yml

    Paste the following. NPM runs in host network mode, so it listens directly on the server’s ports 80, 443 and 81 and can reach other apps at 127.0.0.1:

    yaml 
    services:
  npm:
    image: 'jc21/nginx-proxy-manager:latest'
    container_name: npm
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./data:/data
      - ./letsencrypt:/etc/letsencrypt

    Save with Ctrl + O, Enter, and exit with Ctrl + X.

    💡
    Optional: GoAccess traffic stats. The video’s Compose file also includes a GoAccess container that reads NPM’s logs and shows who is visiting your sites. It is not required; skip it if you do not want it. To add it, paste this under services: (indented two spaces, like npm:) and open http://SERVER-IP:7880 afterwards.
    yaml 
      goaccess:
    image: xavierh/goaccess-for-nginxproxymanager:latest
    container_name: goaccess
    restart: unless-stopped
    ports:
      - '7880:7880'
    environment:
      - TZ=America/New_York
      - SKIP_ARCHIVED_LOGS=False
      - LOG_TYPE=NPM
    volumes:
      - ./data/logs:/opt/log

    Step 3: Start it

    bash 
    sudo docker compose up -d
sudo docker compose ps

    The first start pulls the images, then the status shows running.

    Step 4: Log in and create your admin account

    ▶ Watch this step (3:55)

    Open http://localhost:81 on the server, or http://SERVER-IP:81 from another computer on your network.

    • Log in with the default Email: admin@example.com and Password: changeme.
    • NPM immediately asks you to change the name, email and password. Use your real email and a strong password.
    • Newer versions of NPM skip the default login and ask you to create the admin account on the first visit instead.

    Get a Wildcard SSL Certificate (Cloudflare DNS Challenge)

    Because the apps will only be reachable over Tailscale, Let’s Encrypt cannot reach the server to verify it. Instead, NPM proves you own the domain by creating a DNS record through Cloudflare’s API (a DNS challenge). One wildcard certificate for *.tail.example.com then covers every private app: vault.tail.example.com, and anything you add later.

    Step 1: Create a Cloudflare API token

    ▶ Watch this step (6:41)

    1. Log in to dash.cloudflare.com.
    2. Go to My Profile → API Tokens → Create Token.
    3. Next to Edit zone DNS, click Use template.
    4. Under Zone Resources, choose Include → Specific zone → your domain.
    5. Click Continue to summary, then Create Token.
    6. Copy the token and keep it somewhere safe for the next step. Cloudflare only shows it once.

    Step 2: Request the certificate in NPM

    ▶ Watch this step (6:06)

    In NPM, go to SSL Certificates → Add SSL Certificate → Let’s Encrypt and fill in:

    SettingValue
    Domain Names*.tail.example.com (type it, then press Enter)
    Email Address for Let’s Encryptyour email
    Use a DNS ChallengeOn
    DNS ProviderCloudflare
    Credentials File Contentreplace the example token with yours (see below)
    I Agree to the Let’s Encrypt TermsOn

    The Credentials File Content box should contain exactly one line with your token:

    ini 
    dns_cloudflare_api_token = PASTE-YOUR-CLOUDFLARE-TOKEN-HERE

    Click Save. After a minute the certificate appears in the list with an expiry date. NPM renews it automatically.

    ℹ
    Replace example.com with your own domain everywhere on this page. The tail part is just a label that groups your Tailscale-only apps; you can pick another word, but keep it the same everywhere.

    Add a Proxy Host

    Each app gets its own proxy host. The Vault Warden section shows the exact values for Vaultwarden.

    1. Go to Hosts → Proxy Hosts → Add Proxy Host.
    2. Details tab: enter the full domain (e.g. app.tail.example.com), Scheme http, Forward Hostname 127.0.0.1 (NPM is in host mode), and the port the app is published on.
    3. SSL tab: choose the *.tail.example.com wildcard certificate, and turn on Force SSL, HTTP/2 Support and HSTS Enabled.
    4. Click Save.

    Updating and Troubleshooting

    Update Nginx Proxy Manager

    bash 
    cd ~/docker/npm
sudo docker compose pull
sudo docker compose up -d
sudo docker image prune -f

    View the logs

    Follow the logs live (press Ctrl + C to stop):

    bash 
    cd ~/docker/npm
sudo docker compose logs -f

    NPM will not start: “address already in use”

    Something else (often Apache or a regular NGINX install) is already using port 80 or 443. Find it and turn it off:

    bash 
    sudo ss -tulpn | grep -E ":80 |:443 "
    bash 
    sudo systemctl disable --now apache2
sudo systemctl disable --now nginx

    The certificate request fails

    • Check the API token was created from the Edit zone DNS template and includes your domain.
    • Check the credentials line has no extra spaces or quotes around the token.
    • Wait a few minutes and try again; Let’s Encrypt limits repeated failed attempts.

    502 Bad Gateway

    NPM cannot reach the app. Check the app is running and published on the port you entered:

    bash 
    sudo docker ps

    Connect the Server to Tailscale

    ▶ Watch this step (4:33)

    Tailscale puts your server and your devices on a private, encrypted WireGuard network (your tailnet) so you can reach the vault from anywhere without opening any ports.

    1. Create a free account at tailscale.com.
    2. In the admin console, click Add device → Linux server.
    3. Set the auth key expiry to 1 day (it is only used now), then click Generate install script and copy it.
    4. Paste the script into the server’s terminal and run it. It looks like the commands below.
    bash 
    curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

    Back in the Tailscale admin console under Machines, the server now appears with a Tailscale IP address starting with 100.. You can also print it on the server:

    bash 
    tailscale ip -4

    Copy this IP. The DNS record in the next step points to it.

    Point the Domain at Your Tailscale IP

    ▶ Watch this step (7:52)

    This public DNS record points to a private Tailscale address, so it only leads anywhere for devices that are on your tailnet. Everyone else gets nowhere.

    1. In Cloudflare, open your domain and go to DNS → Records → Add record.
    2. Fill in the record using the table below, then click Save.
    SettingValue
    TypeA
    Name*.tail
    IPv4 addressyour server’s Tailscale IP (100.x.y.z)
    Proxy statusDNS only (grey cloud, not proxied)

    Deploy Vaultwarden

    ▶ Watch this step (8:30)

    Step 1: Create a folder

    bash 
    mkdir -p ~/docker/vault
cd ~/docker/vault

    Step 2: Create the Compose file

    This is the Compose example from the Vaultwarden GitHub page, with two changes: the port is mapped to 1776 (NPM already uses 80), and DOMAIN is set to your vault address.

    bash 
    nano docker-compose.yml
    yaml 
    services:
  vaultwarden:
    image: vaultwarden/server:latest
    container_name: vaultwarden
    restart: unless-stopped
    environment:
      DOMAIN: "https://vault.tail.example.com"
    volumes:
      - ./vw-data/:/data/
    ports:
      - 1776:80
    💡
    Optional hardening: change the port line to - 127.0.0.1:1776:80. Vaultwarden is then only reachable through NPM (which forwards to 127.0.0.1), not directly on port 1776 from your local network.

    Step 3: Start it

    bash 
    sudo docker compose up -d
sudo docker compose ps

    Create the Proxy Host in NPM

    SettingValue
    Domain Namesvault.tail.example.com

    SSL tab → SSL Certificatethe *.tail.example.com wildcard
    SSL tab → optionsForce SSL, HTTP/2 Support, HSTS Enabled

    Click Save, then browse to https://vault.tail.example.com from the server. You should see the Vaultwarden login page with a padlock.

    Enable the Server Admin Page

    ▶ Watch this step (20:00)

    The admin page at /admin manages the whole server: view and delete users, and reset a user’s two-step login if they lose their phone. It is off until you give it a password.

    Step 1: Generate a hashed admin token

    With Vaultwarden running, run the hash tool inside the container and type a strong admin password twice:

    bash 
    cd ~/docker/vault
sudo docker exec -it vaultwarden /vaultwarden hash

    It prints a line starting with ADMIN_TOKEN=. Copy the whole line.

    Step 2: Save it in a .env file

    bash 
    nano .env

    Paste the line. It looks like this (yours will be longer), including the single quotes:

    env 
    ADMIN_TOKEN='$argon2id$v=19$m=65540,t=3,p=4$PASTE-YOUR-HASH-HERE'

    Save, exit, and make the file private:

    bash 
    chmod 600 .env

    Step 3: Add it to the Compose file

    bash 
    nano docker-compose.yml

    Add the ADMIN_TOKEN line inside the environment: block, so it reads:

    yaml 
        environment:
      DOMAIN: "https://vault.tail.example.com"
      ADMIN_TOKEN: ${ADMIN_TOKEN}

    Step 4: Restart and log in

    bash 
    sudo docker compose down
sudo docker compose up -d

    Go to https://vault.tail.example.com/admin and enter the admin password you typed in Step 1 (the plain password, not the hash).

    Back up the vault

    Everything lives in vw-data. Stop the container briefly so the database is consistent, archive the folder, then start it again:

    bash 
    cd ~/docker/vault
sudo docker compose stop
sudo tar -czf ~/vaultwarden-backup-$(date +%F).tar.gz -C ~/docker/vault vw-data .env docker-compose.yml
sudo docker compose start
ls -lh ~/vaultwarden-backup-*.tar.gz
    💡
    Copy backups off the server (another machine, a NAS, or cloud storage). See RAID for protecting against a failed disk.

    Restore from a backup

    bash 
    cd ~/docker/vault
sudo docker compose down
sudo tar -xzf ~/vaultwarden-backup-YYYY-MM-DD.tar.gz -C ~/docker/vault
sudo docker compose up -d

    bash 
    cd ~/docker/vault
sudo docker compose pull
sudo docker compose up -d
sudo docker image prune -f

    Troubleshooting

    • The site does not load anywhere: check the device is connected to Tailscale, and that the *.tail A record points to the server’s current Tailscale IP (tailscale ip -4).
    • Certificate warning in the browser: the proxy host is not using the wildcard certificate, or the domain is not under tail.example.com.
    • 502 Bad Gateway: Vaultwarden is not running or not on port 1776. Run sudo docker ps.
    • Admin page says the token is invalid: make sure the whole ADMIN_TOKEN='...' line is in .env with its single quotes, then run sudo docker compose down and sudo docker compose up -d.
    • Devices do not sync instantly: turn on Websockets Support on the proxy host in NPM.

    RAID

    RAID (Redundant Array of Independent Disks) combines several physical drives into one logical drive for more speed, more redundancy, or both. This guide builds a software RAID on Ubuntu Server with mdadm, entirely over SSH. No hardware RAID card is needed.

    ⚠
    Creating an array erases every disk you add to it. Back up anything on those disks first, and double-check the device names before running the create command.
    ℹ
    RAID is not a backup. It keeps the server running when a disk dies, but it will happily mirror an accidental delete, ransomware, or a corrupted file to every disk. Keep separate backups.

    Choosing a RAID Level

    LevelMin. disksUsable spaceSurvivesBest for
    RAID 0 (stripe)2100% of all disksNo disk failuresScratch space, speed only. Losing one disk loses everything.
    RAID 1 (mirror)2Size of one diskAll but one diskBoot/OS data, small home servers. Simple and safe.
    RAID 5 (parity)3Total − 1 disk1 diskMedia and file storage with a good balance of space and safety.
    RAID 6 (double parity)4Total − 2 disks2 disksLarge arrays of big drives, where rebuilds take a long time.
    RAID 10 (mirror + stripe)450% of all disks1 disk per mirror pairVMs and databases that need speed and redundancy.

    Use disks of the same size. The array treats every member as the size of the smallest one.

    Setting Up a RAID Array over SSH

    The examples below use the disks /dev/sdb, /dev/sdc, /dev/sdd and /dev/sde, the array name /dev/md0, and the mount point /mnt/raid. Replace the disk names with your own from Step 3.

    Step 1: Connect to the server

    From your computer, open a terminal (PowerShell on Windows) and connect:

    bash 
    ssh username@server-ip
    💡
    If you lose the SSH connection while the array is building, nothing breaks. The build keeps running on the server. Just reconnect and check progress with cat /proc/mdstat.

    Step 2: Update the system and install mdadm

    bash 
    sudo apt update
sudo apt upgrade -y
sudo apt install mdadm -y

    If the installer shows a mail configuration screen (Postfix), choose No configuration unless you already run a mail server.

    Step 3: Identify the disks

    List every disk with its size and whether it is already in use:

    bash 
    lsblk -o NAME,SIZE,FSTYPE,TYPE,MOUNTPOINTS

    For more detail, including the model of each disk:

    bash 
    sudo fdisk -l

    The new, empty disks usually show no partitions and no mount point. Write down their names (for example sdb, sdc).

    ⚠
    Do not use the disk that holds Ubuntu. It is the one with partitions mounted at / or /boot, usually sda or nvme0n1.

    Step 4: Wipe old data from the disks

    Remove any old partition tables or filesystem signatures (list every disk you will use):

    bash 
    sudo wipefs -a /dev/sdb /dev/sdc

    If a disk was ever part of another RAID array, also clear its old RAID metadata. An error saying “Unrecognised md component device” just means there was nothing to clear.

    bash 
    sudo mdadm --zero-superblock /dev/sdb /dev/sdc

    Step 5: Create the array

    Run only the one command for the RAID level you chose. When asked Continue creating array?, type y and press Enter.

    RAID 1 (2 disks):

    bash 
    sudo mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc

    RAID 5 (3 disks):

    bash 
    sudo mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 /dev/sdb /dev/sdc /dev/sdd

    RAID 6 (4 disks):

    bash 
    sudo mdadm --create --verbose /dev/md0 --level=6 --raid-devices=4 /dev/sdb /dev/sdc /dev/sdd /dev/sde

    RAID 10 (4 disks):

    bash 
    sudo mdadm --create --verbose /dev/md0 --level=10 --raid-devices=4 /dev/sdb /dev/sdc /dev/sdd /dev/sde

    RAID 0 (2 disks, no redundancy):

    bash 
    sudo mdadm --create --verbose /dev/md0 --level=0 --raid-devices=2 /dev/sdb /dev/sdc

    Step 6: Watch the initial sync

    RAID 1, 5, 6 and 10 now sync the disks in the background. This can take hours on large drives. Check progress:

    bash 
    cat /proc/mdstat

    Or refresh it every 5 seconds (press Ctrl + C to stop watching):

    bash 
    watch -n 5 cat /proc/mdstat

    You can keep going with the next steps while it syncs. The array is usable right away, just slower until the sync finishes.

    Step 7: Create a filesystem

    bash 
    sudo mkfs.ext4 -F /dev/md0

    Step 8: Mount the array

    bash 
    sudo mkdir -p /mnt/raid
sudo mount /dev/md0 /mnt/raid

    Confirm it is mounted and shows the expected size:

    bash 
    df -h /mnt/raid

    Step 9: Make the array survive a reboot

    Save the array layout so Ubuntu reassembles it at boot:

    bash 
    sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
sudo update-initramfs -u
    ⚠
    Run the tee -a command above only once. Running it twice adds a duplicate ARRAY line. If that happens, open the file with sudo nano /etc/mdadm/mdadm.conf and delete the extra line.

    Add the array to /etc/fstab by its UUID so it mounts automatically. nofail lets the server still boot if the array has a problem:

    bash 
    echo "UUID=$(sudo blkid -s UUID -o value /dev/md0) /mnt/raid ext4 defaults,nofail 0 2" | sudo tee -a /etc/fstab

    Test the fstab entry without rebooting. No output from mount -a means it worked:

    bash 
    sudo umount /mnt/raid
sudo mount -a
findmnt /mnt/raid

    Step 10: Give your user access

    The new filesystem is owned by root. Let your own account read and write to it:

    bash 
    sudo chown -R $USER:$USER /mnt/raid

    Step 11: Reboot and verify

    bash 
    sudo reboot

    Wait a minute, reconnect with SSH, then check the array:

    bash 
    ssh username@server-ip
    bash 
    cat /proc/mdstat
sudo mdadm --detail /dev/md0
df -h /mnt/raid

    In the mdadm --detail output, look for State : clean (or active) and every disk listed as active sync.

    Checking Health and Replacing a Failed Disk

    Check array health

    bash 
    cat /proc/mdstat
sudo mdadm --detail /dev/md0

    In /proc/mdstat, [UU] means every disk is up. An underscore, such as [U_], means a disk has failed or is missing and the array is running degraded.

    Check a single disk’s own health report (install the tools first):

    bash 
    sudo apt install smartmontools -y
sudo smartctl -H /dev/sdb

    Replace a failed disk

    1. Find which disk failed (it is marked faulty or removed):

    bash 
    sudo mdadm --detail /dev/md0

    2. Mark the disk as failed and remove it from the array (replace /dev/sdc with the failed disk):

    bash 
    sudo mdadm /dev/md0 --fail /dev/sdc
sudo mdadm /dev/md0 --remove /dev/sdc

    3. Note the failed disk’s serial number so you pull the right physical drive, then shut down and swap it:

    bash 
    sudo smartctl -i /dev/sdc | grep -i serial
sudo shutdown now

    4. After booting back up and reconnecting over SSH, find the new disk’s name with lsblk, then add it to the array (here the new disk is /dev/sdf):

    bash 
    lsblk -o NAME,SIZE,FSTYPE,TYPE,MOUNTPOINTS
sudo wipefs -a /dev/sdf
sudo mdadm /dev/md0 --add /dev/sdf

    5. Watch the rebuild until it reaches 100%:

    bash 
    watch -n 5 cat /proc/mdstat

    Troubleshooting

    The array shows up as /dev/md127 after a reboot

    The layout was not saved in Step 9. Stop the array, reassemble it under the right name, and save the config:

    bash 
    sudo umount /mnt/raid
sudo mdadm --stop /dev/md127
sudo mdadm --assemble --scan
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
sudo update-initramfs -u
sudo mount -a

    The array is inactive or not mounted after a reboot

    bash 
    sudo mdadm --assemble --scan
sudo mount -a
cat /proc/mdstat

    “Device or resource busy” when creating or stopping the array

    Something is still using the disk. Check for mount points, then unmount before trying again:

    bash 
    lsblk -o NAME,MOUNTPOINTS
sudo umount /dev/sdb1

    Deleting an array completely

    ⚠
    This permanently destroys all data on the array.
    bash 
    sudo umount /mnt/raid
sudo mdadm --stop /dev/md0
sudo mdadm --zero-superblock /dev/sdb /dev/sdc

    Then remove the /dev/md0 line from /etc/mdadm/mdadm.conf and the /mnt/raid line from /etc/fstab (sudo nano each file), and run sudo update-initramfs -u.
