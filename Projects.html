Hypervisors

What it is: A hypervisor is software that runs several virtual machines (VMs) on one physical computer, giving each VM its own share of CPU, memory and storage. Type 1 (bare-metal) hypervisors such as Proxmox, VMware ESXi and Hyper-V run directly on the hardware, which makes them the foundation of most home labs and data centers.

Proxmox

What it is: Proxmox VE (Virtual Environment) is a free, open-source Type 1 hypervisor built on Debian Linux. It runs full virtual machines (KVM) and lightweight Linux containers (LXC) side by side, all managed from a web interface with built-in backups, snapshots and clustering.

Core Services

What it is: Core services are the basic tools installed on almost every Linux server before anything else: secure remote access (Tailscale, SSH and key-based login), a way to run applications (Docker and Docker Compose), and everyday command-line utilities for downloading files, watching performance, editing configuration files and troubleshooting the network.

Tailscale

What it is: Tailscale is a mesh VPN built on WireGuard. It links your computers, servers and phones into one private network (a “tailnet”), so they can reach each other securely from anywhere without opening ports on your router.

Connect to your remote server via SSH:

bash 
ssh user@your_server_ip

Ensure you have sudo privileges on the target machine.

Install Tailscale

Update package list (Debian/Ubuntu):

bash 
sudo apt update && sudo apt install -y curl

Download & install Tailscale:

bash 
curl -fsSL https://tailscale.com/install.sh | sh

This installs the latest version for your OS automatically.

Authenticate Server

Start Tailscale service:

bash 
sudo tailscale up

You will see an authentication URL: "To authenticate, visit: https://login.tailscale.com/a/xxxxxx"

Copy the URL from SSH output and open it on your local browser.

  • Log in with your preferred identity provider (Google, GitHub, Microsoft, etc.)
  • Once authenticated, the machine will appear in your Tailscale admin dashboard.

SSH

What it is: SSH (Secure Shell) is the standard way to log in to and manage a Linux machine from another computer. Everything you type and see is encrypted, so you can run commands on a server as if you were sitting in front of it.

Install OpenSSH Server:

bash 
sudo apt update
sudo apt upgrade
sudo apt install openssh-server -y

Verify it is running:

bash 
sudo systemctl status ssh

Allow through the Firewall:

bash 
sudo ufw allow ssh

Docker

What it is: Docker runs applications in containers: lightweight, isolated packages that bundle an app with everything it needs. A container runs the same way on any machine, so installing, updating or removing a service is one command and never clutters the host system.

Documentation: https://docs.docker.com/engine/install

# Add Docker's official GPG key:

bash 
sudo apt update
sudo apt install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# Add the repository to Apt sources:

bash 
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc
EOF

Install the Docker packages:

bash 
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo apt update
sudo systemctl status docker
sudo systemctl start docker
sudo docker run hello-world

Docker Compose

What it is: Docker Compose describes one or more containers (their images, ports, volumes and settings) in a single docker-compose.yml file, then starts or stops the whole stack with one command. It is how most of the self-hosted apps on this page are deployed.

Documentation: https://docs.docker.com/compose/install/

CURL

What it is: curl is a command-line tool for sending and receiving data over URLs. It is used to download files and install scripts, test websites and APIs, and check whether a service is responding.

bash 
sudo apt install ca-certificates curl

Htop

What it is: htop is an interactive, color-coded process viewer for the terminal. It shows live CPU, memory and swap usage alongside every running process, and lets you sort, search and stop processes. It is the quickest way to see what is slowing a server down.

Depending on your Linux distribution, use the corresponding command below:

For Ubuntu, Debian, Linux Mint, or Kali:

bash 
sudo apt update
sudo apt install htop

For CentOS, RHEL, or Rocky Linux:

bash 
# First, enable the EPEL repository
sudo dnf install epel-release
# Then install htop
sudo dnf install htop

For Fedora:

bash 
sudo dnf install htop

For Arch Linux:

bash 
sudo pacman -S htop

How to use htop

Once installed, simply type htop in your terminal to launch it.

Quick Cheat Sheet for htop:

Once the interface is open, you can use these keyboard shortcuts to navigate:

  • F2 (Setup): Customize the colors, meters, and columns.
  • F3 (Search): Find a specific process by name.
  • F4 (Filter): Hide everything except processes matching your keyword.
  • F5 (Tree): See the parent-child relationship between processes.
  • F6 (Sort): Choose to sort by CPU%, Memory%, PID, etc.
  • F9 (Kill): Send a signal (like SIGKILL) to stop a process safely.
  • F10 (Quit): Exit the program.

Vim/Nano

What it is: Vim and Nano are text editors that run in the terminal, used to edit configuration files directly on a server. Nano is simple, with its shortcuts listed at the bottom of the screen; Vim is more powerful and keyboard-driven, with a steeper learning curve.

Installation Steps

For Ubuntu, Debian, or Raspberry Pi OS:

bash 
sudo apt update
sudo apt install nano vim

For CentOS, RHEL, or Rocky Linux:

bash 
sudo dnf install nano vim-enhanced

For Arch Linux:

bash 
sudo pacman -S nano vim

How to use them

Using Nano:

  • To open a file: nano filename.txt
  • Save: Press Ctrl + O then Enter.
  • Exit: Press Ctrl + X.
  • Search: Press Ctrl + W.

Using Vim:

  • To open a file: vim filename.txt
  • Type Text: Press i to enter Insert Mode.
  • Stop Typing: Press Esc to return to Normal Mode.
  • Save & Exit: In Normal Mode, type :wq and hit Enter.
  • Exit without Saving: In Normal Mode, type :q! and hit Enter.

Net-tools

What it is: Net-tools is a package of classic Linux networking commands such as ifconfig, netstat, route and arp. They show network interfaces and IP addresses, open ports and connections, and the routing table, which makes them handy for troubleshooting connectivity.

Installation Steps

For Ubuntu, Debian, Linux Mint, or Kali:

bash 
sudo apt update
sudo apt install net-tools

For CentOS, RHEL, Fedora, or Rocky Linux:

bash 
sudo dnf install net-tools

For Arch Linux:

bash 
sudo pacman -S net-tools

What's inside net-tools

Command What it does Modern Replacement (iproute2)
ifconfig View/Configure network interfaces ip addr
netstat -tuln See active ports and connections ss -tuln
route -n View the routing table ip route
arp -a View the ARP table (IP-to-MAC mapping) ip neigh

Quick Examples

Check your IP address: shows each network interface with its hardware (MAC) address, local IP address (inet) and packet statistics.

bash 
ifconfig

Check listening ports: shows which programs are listening on which ports (for example, port 80 for HTTP).

bash 
sudo netstat -plnt

Check your default gateway: shows the routing table; the line with destination 0.0.0.0 is your default gateway (usually your router).

bash 
route -n

Samba

What it is: Samba lets a Linux machine share folders with Windows, macOS and other Linux computers using SMB, the same file-sharing protocol Windows uses. Shared folders show up in File Explorer like any other network drive, which makes Samba the usual way to turn a Linux server into a home file server or NAS.

Step 1: Install Samba

For Ubuntu/Debian:

bash 
sudo apt update
sudo apt install samba

Step 2: Create the Shared Directory

bash 
sudo mkdir -p /samba/public
sudo chmod -R 0777 /samba/public
sudo chown -R nobody:nogroup /samba/public

Step 3: Configure the Samba Share

bash 
sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.bak
sudo nano /etc/samba/smb.conf

Add your share details at the bottom:

config 
[PublicShare]
comment = Samba on Ubuntu
path = /samba/public
browsable = yes
read only = no
guest ok = yes
force user = nobody

Step 4: Setup User Accounts (Optional but Recommended)

If you want a private share instead of a guest one, you must create a Samba password for your user.

bash 
sudo smbpasswd -a your_username
sudo smbpasswd -e your_username

Step 5: Restart Samba

bash 
sudo systemctl restart smbd nmbd
sudo ufw allow samba

Step 6: How to Access the Share

From Windows:

  1. Open File Explorer
  2. In the address bar, type: \\<YOUR_STATIC_IP>\PublicShare (e.g., \\192.168.38.120\PublicShare)
  3. Press Enter

From Linux:

  1. Open your file manager (Nautilus, Thunar, etc.)
  2. Select "Other Locations" or "Connect to Server"
  3. Enter: smb://192.168.38.120/PublicShare

Summary of smb.conf Parameters

Parameter Meaning
path The actual directory on your Linux disk
browsable Whether the share shows up when browsing the network
read only Set to no if you want to be able to upload/delete files
guest ok Set to yes to allow access without a username/password

Static IP

What it is: A static IP address is one you set manually so it never changes, unlike a dynamic address that your router hands out through DHCP and may change after a reboot. Servers need a static IP so that port forwarding, DNS records, bookmarks and other devices can always find them at the same address.

Windows

What it is: On Windows, a static IP is set in the network adapter’s IPv4 properties: instead of obtaining an address automatically, you enter the IP address, subnet mask, default gateway and DNS servers yourself.

  1. Go to Control Panel.
  2. Select Network and Internet.
  3. Go to Network and Sharing Center.
  4. Click on your active connection (e.g., Connections: Ethernet).
  5. Select Properties.
  6. Click on Internet Protocol Version 4 (TCP/IPv4) and select Properties.
  7. Here a static IP, Subnet mask, and Default gateway can be manually set.

DNS

What it is: DNS (Domain Name System) is the internet’s phone book: it translates names like ryanpgray.com into the IP addresses computers use to connect. Records at your DNS provider decide where a domain and its subdomains point: A records for IPv4 addresses, CNAME records for aliases, and MX records for email.

Deploy an HTML Site

What it is: Deploying an HTML site means putting your pages on a web server that is always online, so anyone can open them in a browser. This guide uses GitHub Pages, a free service that publishes static sites (HTML, CSS, JavaScript and images) straight from a GitHub repository, then connects a custom domain such as yourname.com using DNS records and turns on free HTTPS.

These steps follow the video tutorial below (SuperSimpleDev). Each step links to the matching point in the video.

Video Tutorial: https://youtu.be/p1QU3kLFPdg

Before You Start

  • A website made of HTML and CSS files on your computer. No website yet? Download the video’s sample site: open it on GitHub, click Code → Download ZIP, and unzip it.
  • A free GitHub account.
  • For Part 2 only: about $10–15 a year for a domain name.

Useful links:

  • Namecheap: domain registrar used in the video
  • MxToolbox DNS Lookup: shows which IP addresses a domain points to
  • GitHub Docs: Managing a custom domain: GitHub’s own IP addresses and instructions for other registrars

Part 1: Put the Website on the Internet (GitHub Pages)

Opening an HTML file on your own computer only works for you. GitHub Pages copies your files to GitHub’s web servers so anyone can reach them.

▶ Watch this step (2:08)

Step 1: Sign in to GitHub

Go to github.com and sign in, or sign up for a new account and then sign in.

Step 2: Create a public repository

A repository is like a folder on GitHub that holds your website’s files.

  1. Click your profile icon (top right) → Your repositories → New.
  2. Repository name: anything that helps you recognize it, for example super-simple-website.
  3. Select Public. GitHub Pages is only free for public repositories.
  4. Leave the other options at their defaults and click Create repository.

Step 3: Upload your website’s files

▶ Watch this step (3:34)

  1. In the new repository, click uploading an existing file. If you don’t see the link, add /upload to the end of the repository’s URL.
  2. On your computer, open your website’s folder, select everything inside it, and drag the files into the upload box.
  3. Wait for every file to finish uploading, scroll to the bottom and click Commit changes.
⚠
Drag the files inside your folder, not the folder itself. Dragging the folder adds an extra folder level in the repository, and your pages end up at the wrong address.

Step 4: Turn on GitHub Pages

▶ Watch this step (4:50)

  1. In the repository, click Settings (top tab) → Pages (left menu).
  2. Under Build and deployment, set the branch drop-down to main (it may say master; pick whichever isn’t None). Leave the folder as / (root).
  3. Click Save.
  4. Wait a couple of minutes, then refresh the page. It will say Your site is live at followed by the address.

Your site’s default address always follows this pattern:

url 
https://YOUR-USERNAME.github.io/REPOSITORY-NAME/

Step 5: Open your site

▶ Watch this step (5:57)

Open the address in a new tab. If you see a 404 page, that’s normal at this point: add the name of one of your HTML files to the end of the address, for example …/REPOSITORY-NAME/youtube.html, and your page loads. The next step fixes the 404.

Step 6: Add an index.html so the home page loads

▶ Watch this step (8:23)

When an address doesn’t name a file, the web server looks for index.html. No index.html means a 404. Make your main page the home page by renaming it:

  1. In the repository, click your main HTML file (e.g. youtube.html) and click the pencil (Edit this file).
  2. Change the file name at the top to index.html.
  3. Click Commit changes, wait a minute or two, and refresh your site’s address. The home page now loads without a file name.
ℹ
How it works: the repository behaves exactly like the folder on your computer. If your HTML loads styles/general.css locally, it loads the same file from the repository, and images and other files work the same way. So the workflow is simply: build the site on your computer, upload the files, and GitHub Pages publishes them. Every new commit republishes the site within a few minutes.

How the Browser Finds Your Site

▶ Watch this step (15:37)

Before linking the domain, it helps to know what’s happening behind the scenes:

  • Web server: software that hands out files when a browser asks for them. Ask for /index.html and it returns that file; the browser displays HTML as a page. (VS Code’s Live Server is a small web server on your own computer.)
  • Host: the computer the web server runs on. GitHub hosts the servers for GitHub Pages.
  • IP address: like a phone number for every device on the internet. IPv4 looks like 185.199.108.153; IPv6 is longer and exists because IPv4 numbers are running out.
  • DNS record: the link between a domain name and an address, set at your registrar. Once it points your domain at GitHub, typing your domain makes the browser contact GitHub’s servers. See also DNS.

Part 3: Point the Domain at GitHub Pages (DNS Records)

Step 1: Open your domain’s DNS settings

▶ Watch this step (18:51)

In Namecheap: Account → sign in → Domain List → Manage next to your domain → Advanced DNS. Scroll to the Host Records table.

ℹ
Using a different registrar? Look for its DNS records or Manage DNS page (search “manage DNS records” plus your registrar’s name). Every registrar asks for the same four values: Type, Host, Value and TTL.

Step 2: Understand the four values

  • Type: what the record links to. An A record links a name to an IPv4 address; a CNAME record links a name to another domain name.
  • Host: the subdomain, the part before your domain (like studio in studio.youtube.com). Use @ on Namecheap for the bare domain with no subdomain; some registrars leave it blank.
  • Value: the IP address or domain the record points to.
  • TTL (time to live): how quickly changes spread across the internet. Choose 5 min, or enter 300 (seconds) if there’s no drop-down.

Step 3: Find GitHub Pages’ IP addresses

▶ Watch this step (21:56)

Open MxToolbox DNS Lookup, enter YOUR-USERNAME.github.io and click DNS Lookup. It lists four IPv4 addresses. Or look them up from a terminal:

bash 
nslookup YOUR-USERNAME.github.io

At the time of writing, GitHub Pages uses these four addresses (confirm them with the lookup or GitHub’s docs):

text 
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153

Step 4: Add four A records

▶ Watch this step (22:20)

Click Add New Record once for each address:

TypeHostValueTTL
A Record@185.199.108.1535 min

💡
When you save your first record, Namecheap’s default parking records may disappear. That’s expected; they only exist while the domain has no records of its own.

Step 5: Add a CNAME record for www

▶ Watch this step (24:00)

GitHub recommends also setting up www.yourdomain.com. Add one more record:

TypeHostValueTTL
CNAME RecordwwwYOUR-USERNAME.github.io5 min

Click the checkmark (Save All Changes) to save.

ℹ
Why not a CNAME for the bare domain too? A CNAME can only be used on a subdomain such as www, never on the bare domain itself, so the bare domain uses A records.
Optional: also add GitHub’s IPv6 addresses as AAAA records (listed in GitHub’s docs). Not required today, but it future-proofs the setup.

Part 4: Connect the Domain in GitHub Pages

▶ Watch this step (26:06)

  1. Go back to your repository on GitHub → Settings → Pages.
  2. Under Custom domain, type your domain (e.g. yourname.com) and click Save. GitHub runs a DNS check.
  3. Open your domain in a new tab. It now shows your site, though the browser may say Not secure until the next part.
⏳
DNS changes can take up to 24–48 hours to reach everyone, depending on the registrar. If the domain doesn’t work yet, wait and try again later. Most of the time it works within minutes.

Check whether your records are live from a terminal:

bash 
nslookup yourname.com
nslookup www.yourname.com

The first should return the four 185.199.x.153 addresses; the second should show it’s an alias of YOUR-USERNAME.github.io.

Part 5: Turn On HTTPS (Free)

▶ Watch this step (27:32)

HTTPS encrypts everything sent between the browser and your site, so no one can read it in transit, and removes the “Not secure” warning.

  1. In Settings → Pages, find Enforce HTTPS.
  2. If the box is greyed out, GitHub is still issuing your certificate. Wait a few minutes and refresh.
  3. Once it’s clickable, check Enforce HTTPS.
  4. Visit https://yourname.com. A lock icon in the address bar means HTTPS is working.

Windows Server

What it is: Windows Server is Microsoft’s operating system for servers. It runs core business network services such as Active Directory (central user and computer accounts), DNS, DHCP, file sharing and Group Policy, and is the backbone of most corporate Windows networks.

Section 1: Initial Server Setup & Role Installation

Before beginning, ensure your server has a static IP address configured (e.g., 192.168.49.5)

  1. Open Server Manager: Click Manage > Add Roles and Features
  2. Select Installation Type: Choose Role-based or feature-based installation and select your server
  3. Select Server Roles: Check the boxes for:
    • Active Directory Domain Services (AD DS)
    • DHCP Server
    • DNS Server
    • Note: Click "Add Features" whenever prompted for management tools.
  4. Install: Follow the prompts and click Install
  5. Promote to Domain Controller: Once installed, click the notification flag and select Promote this server to a domain controller
  6. Deployment: Select Add a new forest and enter your Root domain name (e.g., mylab.local)
  7. Configuration: Set a Directory Services Restore Mode (DSRM) password and complete the wizard
  8. The server will automatically reboot after installation.

Section 2: DNS - Configuring Lookup Zones

Active Directory creates Forward Lookup Zones automatically, but you must manually configure the Reverse Lookup Zone.

Configuring Reverse Lookup Zones:

  1. Open DNS Manager: Go to Tools > DNS
  2. Create New Zone: Right-click Reverse Lookup Zones > New Zone
  3. Select Primary Zone and check "Store the zone in Active Directory"

RAID

What it is: RAID (Redundant Array of Independent Disks) combines several physical drives into one logical drive for more speed, more redundancy, or both. This guide builds a software RAID on Ubuntu Server with mdadm, entirely over SSH. No hardware RAID card is needed.

⚠
Creating an array erases every disk you add to it. Back up anything on those disks first, and double-check the device names before running the create command.
ℹ
RAID is not a backup. It keeps the server running when a disk dies, but it will happily mirror an accidental delete, ransomware, or a corrupted file to every disk. Keep separate backups.

Choosing a RAID Level

LevelMin. disksUsable spaceSurvivesBest for
RAID 0 (stripe)2100% of all disksNo disk failuresScratch space, speed only. Losing one disk loses everything.
RAID 1 (mirror)2Size of one diskAll but one diskBoot/OS data, small home servers. Simple and safe.
RAID 5 (parity)3Total − 1 disk1 diskMedia and file storage with a good balance of space and safety.
RAID 6 (double parity)4Total − 2 disks2 disksLarge arrays of big drives, where rebuilds take a long time.
RAID 10 (mirror + stripe)450% of all disks1 disk per mirror pairVMs and databases that need speed and redundancy.

Use disks of the same size. The array treats every member as the size of the smallest one.

Setting Up a RAID Array over SSH

The examples below use the disks /dev/sdb, /dev/sdc, /dev/sdd and /dev/sde, the array name /dev/md0, and the mount point /mnt/raid. Replace the disk names with your own from Step 3.

Step 1: Connect to the server

From your computer, open a terminal (PowerShell on Windows) and connect:

bash 
ssh username@server-ip
💡
If you lose the SSH connection while the array is building, nothing breaks. The build keeps running on the server. Just reconnect and check progress with cat /proc/mdstat.

Step 2: Update the system and install mdadm

bash 
sudo apt update
sudo apt upgrade -y
sudo apt install mdadm -y

If the installer shows a mail configuration screen (Postfix), choose No configuration unless you already run a mail server.

Step 3: Identify the disks

List every disk with its size and whether it is already in use:

bash 
lsblk -o NAME,SIZE,FSTYPE,TYPE,MOUNTPOINTS

For more detail, including the model of each disk:

bash 
sudo fdisk -l

The new, empty disks usually show no partitions and no mount point. Write down their names (for example sdb, sdc).

⚠
Do not use the disk that holds Ubuntu. It is the one with partitions mounted at / or /boot, usually sda or nvme0n1.

Step 4: Wipe old data from the disks

Remove any old partition tables or filesystem signatures (list every disk you will use):

bash 
sudo wipefs -a /dev/sdb /dev/sdc

If a disk was ever part of another RAID array, also clear its old RAID metadata. An error saying “Unrecognised md component device” just means there was nothing to clear.

bash 
sudo mdadm --zero-superblock /dev/sdb /dev/sdc

Step 5: Create the array

Run only the one command for the RAID level you chose. When asked Continue creating array?, type y and press Enter.

RAID 1 (2 disks):

bash 
sudo mdadm --create --verbose /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc

RAID 5 (3 disks):

bash 
sudo mdadm --create --verbose /dev/md0 --level=5 --raid-devices=3 /dev/sdb /dev/sdc /dev/sdd

RAID 6 (4 disks):

bash 
sudo mdadm --create --verbose /dev/md0 --level=6 --raid-devices=4 /dev/sdb /dev/sdc /dev/sdd /dev/sde

RAID 10 (4 disks):

bash 
sudo mdadm --create --verbose /dev/md0 --level=10 --raid-devices=4 /dev/sdb /dev/sdc /dev/sdd /dev/sde

RAID 0 (2 disks, no redundancy):

bash 
sudo mdadm --create --verbose /dev/md0 --level=0 --raid-devices=2 /dev/sdb /dev/sdc

Step 6: Watch the initial sync

RAID 1, 5, 6 and 10 now sync the disks in the background. This can take hours on large drives. Check progress:

bash 
cat /proc/mdstat

Or refresh it every 5 seconds (press Ctrl + C to stop watching):

bash 
watch -n 5 cat /proc/mdstat

You can keep going with the next steps while it syncs. The array is usable right away, just slower until the sync finishes.

Step 7: Create a filesystem

bash 
sudo mkfs.ext4 -F /dev/md0

Step 8: Mount the array

bash 
sudo mkdir -p /mnt/raid
sudo mount /dev/md0 /mnt/raid

Confirm it is mounted and shows the expected size:

bash 
df -h /mnt/raid

Step 9: Make the array survive a reboot

Save the array layout so Ubuntu reassembles it at boot:

bash 
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
sudo update-initramfs -u
⚠
Run the tee -a command above only once. Running it twice adds a duplicate ARRAY line. If that happens, open the file with sudo nano /etc/mdadm/mdadm.conf and delete the extra line.

Add the array to /etc/fstab by its UUID so it mounts automatically. nofail lets the server still boot if the array has a problem:

bash 
echo "UUID=$(sudo blkid -s UUID -o value /dev/md0) /mnt/raid ext4 defaults,nofail 0 2" | sudo tee -a /etc/fstab

Test the fstab entry without rebooting. No output from mount -a means it worked:

bash 
sudo umount /mnt/raid
sudo mount -a
findmnt /mnt/raid

Step 10: Give your user access

The new filesystem is owned by root. Let your own account read and write to it:

bash 
sudo chown -R $USER:$USER /mnt/raid

Step 11: Reboot and verify

bash 
sudo reboot

Wait a minute, reconnect with SSH, then check the array:

bash 
ssh username@server-ip
bash 
cat /proc/mdstat
sudo mdadm --detail /dev/md0
df -h /mnt/raid

In the mdadm --detail output, look for State : clean (or active) and every disk listed as active sync.

Checking Health and Replacing a Failed Disk

Check array health

bash 
cat /proc/mdstat
sudo mdadm --detail /dev/md0

In /proc/mdstat, [UU] means every disk is up. An underscore, such as [U_], means a disk has failed or is missing and the array is running degraded.

Check a single disk’s own health report (install the tools first):

bash 
sudo apt install smartmontools -y
sudo smartctl -H /dev/sdb

Replace a failed disk

1. Find which disk failed (it is marked faulty or removed):

bash 
sudo mdadm --detail /dev/md0

2. Mark the disk as failed and remove it from the array (replace /dev/sdc with the failed disk):

bash 
sudo mdadm /dev/md0 --fail /dev/sdc
sudo mdadm /dev/md0 --remove /dev/sdc

3. Note the failed disk’s serial number so you pull the right physical drive, then shut down and swap it:

bash 
sudo smartctl -i /dev/sdc | grep -i serial
sudo shutdown now

4. After booting back up and reconnecting over SSH, find the new disk’s name with lsblk, then add it to the array (here the new disk is /dev/sdf):

bash 
lsblk -o NAME,SIZE,FSTYPE,TYPE,MOUNTPOINTS
sudo wipefs -a /dev/sdf
sudo mdadm /dev/md0 --add /dev/sdf

5. Watch the rebuild until it reaches 100%:

bash 
watch -n 5 cat /proc/mdstat

Troubleshooting

The array shows up as /dev/md127 after a reboot

The layout was not saved in Step 9. Stop the array, reassemble it under the right name, and save the config:

bash 
sudo umount /mnt/raid
sudo mdadm --stop /dev/md127
sudo mdadm --assemble --scan
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
sudo update-initramfs -u
sudo mount -a

The array is inactive or not mounted after a reboot

bash 
sudo mdadm --assemble --scan
sudo mount -a
cat /proc/mdstat

“Device or resource busy” when creating or stopping the array

Something is still using the disk. Check for mount points, then unmount before trying again:

bash 
lsblk -o NAME,MOUNTPOINTS
sudo umount /dev/sdb1

Deleting an array completely

⚠
This permanently destroys all data on the array.
bash 
sudo umount /mnt/raid
sudo mdadm --stop /dev/md0
sudo mdadm --zero-superblock /dev/sdb /dev/sdc

Then remove the /dev/md0 line from /etc/mdadm/mdadm.conf and the /mnt/raid line from /etc/fstab (sudo nano each file), and run sudo update-initramfs -u.
